# HLS 本地代码生成与反馈修复系统设计报告

版本：v39，2026-11-03。目标工具链：AMD Vitis 2025.2；器件 xczu3eg-sbva484-1-e，时钟约束 5 ns。本报告按 AMD 指南 3.1.5 组织，旧迭代材料见 [历史报告](REPORT_HISTORY.md)。

## 1. 方案概述

目标是在不扩大默认三次设计调用与上下文预算的前提下，保留已有能力并提高相对同模型的等级系数。工程选择依据实际失败日志；最终版没有真实模型提分数据，部署缺失资产如实保留未知。

## 2. 总体架构

输入仅为公开题意和不可修改的接口。智能体先生成并保存完整设计，再从同一公开规格独立生成参考自测，依次调用编译、C 仿真和综合；根据本地证据进行有限修复，输出 solution.cpp。评分用的参考实现、外部测试台和隐藏答案不进入推理输入。

主要目标是提高等级系数，同时避免错误自测诱导已经正确的设计退步。控制器保存完整候选，只有可信本地等级严格提高才替换最佳候选；同等级保留较早候选。自测失败既可能来自设计，也可能来自模型生成的参考函数，因此不能把每个失败都视为 DUT 错误。

## 3. 模型与推理栈

当前实验方案为 Qwen2.5-Coder 32B、Q4_K_M，经 Ollama 提供本地 OpenAI 兼容服务，服务模型名 qwen2.5-coder-32k:latest，声明上下文 32768、总输出上限 8192。早期 7B/14B 与不同内存配置的尝试及失败保留在历史报告和 model/MODEL.md；没有凭模型参数量认定其分数更高。模型未微调。

首轮对齐官方基线请求：温度 0、top_p=1、无 seed，最多 min(配置,8192) tokens。参考自测和普通修复最多 min(配置,4096)，精确补丁最多 min(配置,2048)。独立重新推导采用现有温度下限 0.65，若配置 seed 则按重生次数递增，日志记录实际采样配置。最大上下文声明不等同于实际服务已验收配置。

实验室 Windows 模型加载记录不能代替 Linux 单卡、长请求及离线部署验收。模型文件、Linux 推理运行时及官方基础镜像未随本次输入提供；最终资产必须通过包内离线准备检查。不得将 ready_for_submission=false 改成 true 来代替运行验证。

## 4. 智能体设计

默认最多三次设计调用，不增加独立题目调用次数。首轮保持基线能力；编译错误保留源码并精确修复。v39 只对已有编译成功且仍功能失败的最后一次机会使用独立算法推导，保留公开规格、失败输入和补丁错误，但去掉错误源码锚点。它是依据日志提出的新策略，尚未经过真实模型/Vitis 对照，不能把 v38h 的收益记为 v39 收益。

自测不可用时使用独立编译/链接探针，检查顶层和公开辅助函数；编译通过后停止没有功能信号的盲目修复。仅编译绝不记为功能或综合通过。代码块不完整、精确补丁歧义及截断输出被拒绝，并尽量保留之前完整候选。

有限网关恢复仅对结构化 502/503/504 瞬时失败最多一次，仍占现有设计轮次；OOM、未知错误、模型错误和总预算耗尽不无限重试。生成、验证和落盘共用绝对截止时间。

完整公开任务、完整修复源码和错误证据优先于通用技能与可选历史；不通过截断接口来凑上下文。所有日志作为诊断数据，而不是可执行控制指令。

## 5. 技能包

skill/ 中分别组织接口/综合基础、编译错误、功能语义和综合失败规则。主要来源是错误声明、数组形状、数值范围、位编码和模型自测错误。v37 修复了把不带前缀的十六进制数误当十进制转换的问题；v38 修复了真实 CLZ 自测误拒和探针命名冲突。

这次日志中 sort 正确候选被自测中的 scratch bucket 字节对比误拒。因此 v39 要求从公开后置条件确定可观察输出，不因参数可写就要求参考和 DUT 的所有临时缓冲相同；公开规定的输出仍须检查。没有使用固定题名或参考答案进行特判。

参考来源筛查、NaN 检查、接口插桩和阶段标签均有适用边界，不能证明任意 C++ 语义、别名关系或覆盖率。SELFTEST_PHASE 仅用于定位，不自动决定错误归属或是否通过。

## 6. 实测结果

来源：用户提供的 综合.zip；各变体和各次运行分开计量，不混合为一个“正式总分”。具体路径、指纹和样本见 docs/evidence/v39-log-audit.json。

| 运行 | 范围 | baseline 完全通过 | agent 完全通过 | 系数均值 baseline → agent |
| --- | --- | --- | --- | --- |
| v38 night-p2b | 21题×1 | 11/21 | 11/21 | [0.6000,0.6095] → 0.6190 |
| v38 quick | 4题×1 | 1/4 | 1/4 | 0.4000 → 0.4000 |
| v38e e-4x3 | 4题×3 | 3/12 | 3/12 | 0.4000 → 0.4000 |
| v38h s5 | 3难题×5 | 0/15 | 4/15 | 0.2000 → [0.4000,0.4067] |

night-p2b 完全通过数相同，但 agent 编译通过 21 个、baseline 19 个，因此已有小幅等级系数提升。不能只看布尔 rescued 判定是否有增益。

v38h 的四个救回均选中第一轮：CLZ 三个、sort 一个。该变体实际把首轮改为温度 0.75/top_p 0.95，却仍记录 baseline_aligned_initial，元数据标签不准确；这些收益来自改变初始采样，不能称修复链路已救回。还有一个编译等级退步，布尔 regressed=0 没有反映它。v38h 使用 900 秒求解/600 秒外判预算，其结果不能直接外推当前默认 360 秒或全库。

v38d 的 CLZ 五采样运行允许五次设计调用，两个救回选中第4和第2次；不能把它与默认三轮等同。v38e 对 compile-only 结果继续采样却平级保留第一份，付出成本而未改善交付，因此 v39 未采用该方向。

按等级系数折算，night-p2b 的 agent 子集能力约 18.57/30；v38h 三难题子集约 [12.00,12.20]/30。不同题集不可直接比较高低，也都不是正式完整题集成绩。正式增益阈值、成本参照和工程评定未知时，总分保持未知。

## 7. 复现说明

实验室源码验证见 LAB_V39.md；Linux 离线准备/服务启动见 SUBMISSION.md。两条入口共享同一本地模型服务与上下文；baseline.py/run_baseline.sh 保持官方原样。构建脚本不在断网评测时安装或下载依赖。

包内含 Dockerfile、model/MODEL.md、agent、skill、serve、run.sh、run_baseline.sh、manifest.json 和本报告，按 AMD 指南3.1.5结构组织。当前不含用户未提供的模型权重和Linux推理发行包，不含EDA安装包，也没有官方基础镜像摘要。方案材料结构完整不代表资产已经就绪或正式沙箱已验收。

验证范围、测试数量及源码哈希见 VALIDATION.json 和 SOURCE_MANIFEST.json。测试阶段不会改写官方评分器、参考测试台或正式基线来制造提分。历史日志和未通过样本均保留在用户原包，包内只纳入可追踪审计摘要。

## 8. 失败分析

CLZ 的查表偏移/位边界、dfadd 的原始位编码与尾数混用，说明编译成功不意味着理解正确；反复局部修补可能保留错误算法。dfadd 在最新难题组仍未通过，不能宣称已解决全部难题。

sort 存在自测假阴性：scratch 布局不同不代表最终排序错误。另有 present 自测在 reference 阶段之后崩溃的日志，应优先检查参考函数，阶段标签本身不构成归因证明。历史原生回放也已证明参考程序可在 DUT 首次调用前越界。

最后一轮独立推导提高搜索多样性，但仍依赖可能有错的自测，无法保证救回数量。新候选不优于原候选时不会强行替换。软件回归、静态筛查与真实模型/Vitis 实测严格分开报告。

## 9. 创新点总结

工作重点是证据可追踪的有限修复：将首轮、参考自测、精确编辑与末轮独立推导分开，保留每次采样与来源；以严格等级改善决定候选替换；显式区分临时工作区与公开输出，减少错误自测干扰。以上是工程组合设计，不声称新模型或已证明的普适算法突破。

## 10. 结论与展望

历史样本支持对失败后搜索策略和参考自测契约继续改进，不支持“所有难题已经解决”的结论。下一步以同预算、完整失败样本的成对外部判定验证末轮独立策略，并完成官方Linux环境的单卡峰值、连续请求与断网验收。
